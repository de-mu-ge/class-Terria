## 一、项目定位

2D 像素风格的生存沙盒游戏，开局用 Galgame 式线性演出交代序章。
核心体验：生态与旅途、伙伴与陪伴；生存是继续前进的理由，寻找朋友是持续前进的目标。
技术形态：Python + 面向对象，参考 Java 的工程设计习惯（类、接口、封装、模块化），参数与文本外置到配置。

## 四、视觉生图工具

- 脚本：`游戏专用skills/视觉生图/generate_image.py`
- 批量清单：`视觉稿/序章_v1/scenes.json`
- 输出：`视觉稿/序章_v1/`，每次运行生成 `manifest.json` 记录提示词与结果
- 密钥：`游戏专用skills/视觉生图/.ark_key`（已在 `.gitignore`，禁止提交、禁止写进代码或提示词正文）

调用约定：

```bash
python 游戏专用skills/视觉生图/generate_image.py --batch 视觉稿/序章_v1/scenes.json --outdir 视觉稿/序章_v1 --no-watermark
```

**配额纪律**：账号总图片用量 **118 张**，用完为止。

- 前期（风格尚未稳定）：可放开用，目标是尽快把风格、UI、色彩定死。
- 后期（风格稳定后）：只用于关键节点——封面、过场、标志性场景、需要人工判断的构图。
- 出图前先 `--dry-run` 校验清单；每张图都应能回答「它改变哪个设计决定」，否则不出。
- 用量自动记录在 `视觉生图/ledger.json`，失败与 dry-run 不计入。

若返回 `429 SetLimitExceeded`（模型被“安全体验模式”暂停），不要反复重试消耗时间，直接告知用户去火山方舟控制台调整额度。

## 五、硬约束

1. 已确定的剧情、台词、人物性格、场景顺序**不得改动**；未确定的世界观谜团**不得编造**（见 `第一轮剧情.md` 第四章）。
2. 视觉风格切换只允许发生在序章 Scene 06 的闪白处；此前不出现像素，此后不出现立绘。
3. 画面文字一律由 UI 层渲染，不交给生图模型生成。
4. 剧情文本、可调参数不写死在代码里。
5. 玩家醒来后的正式玩法场景本轮不制作，但场景管理、玩家对象、状态管理等底层结构必须可接入。

- 改动涉及目录结构、依赖、运行方式时，同步更新项目根记录。
- 面向用户汇报时说明：做了什么、怎么验证、还差什么。
