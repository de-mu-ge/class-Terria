# 初始化构建提示词

## 一、Init 提示部分

1. **开发环境与快速实现**

   这是本项目的第一次构建。为了提高初期开发效率，暂时使用 Conda 虚拟环境 `game`（通过 `conda activate game` 激活）。项目所需依赖由 Agent 根据实际开发需求自行安装。

   当前阶段优先保证项目能够运行、核心框架能够正常工作，不必过早追求复杂的部署方案。

2. **工程设计与可扩展性**

   为了保证未来更换游戏引擎的可行性，充分发挥 Python 面向对象编程的优势。

   - 尽量参考 Java 的工程设计习惯，合理使用类、接口思想、封装和模块化设计。
   - 减少硬编码，将可调整的参数、文本、游戏设定等尽量放入配置文件或独立文本文件。
   - 保持模块之间的低耦合，为未来更换引擎、扩展玩法和多人联机预留空间。
   - 当前阶段不必过度纠结项目目录结构，优先保证设计合理、代码清晰。

3. **游戏专属 Skills**

   本项目需要建立专属的游戏 Skills，与游戏开发同步进行。

   Skills 存放于：

   `./提示词工程部分/游戏专用skills/`

   Skills 用于记录并约束项目的整体风格、开发规范和制作标准，尤其包括：
   - 游戏整体风格与视觉规范
   - 像素美术与场景制作规范
   - 音乐与音效制作规范
   - UI 与对话演出规范

   Skills 不应只是简单的风格描述，还需要尽可能形成可执行的制作指导和质量约束。后续开发应持续完善和遵循这些 Skills。

## 二、User 提示词部分

1. **第一次构建的核心任务**

   本轮构建需要完成以下工作：
   - 游戏专属 Skills 的初始化。
   - 项目开发工作流的搭建。
   - 游戏序章的完整实现。
   - 游戏整体风格的统一。

2. **序章剧情执行**

   序章剧情的具体要求位于：

   `提示词工程部分/操作提示词/epoch提示词/第一轮剧情.md`

   该文件是本轮序章开发的具体执行依据。请严格按照文件中的剧情、场景、人物表现和演出要求实现，不要将其视为参考建议，也不要自行改写剧情或补充未经确定的设定。

3. **核心工程框架**

   本项目除了剧情和场景呈现，还需要逐步建立游戏核心对象体系，包括但不限于：
   - 场景类（Scene）
   - 玩家类（Player）
   - 角色与 NPC 相关对象
   - 游戏状态与资源管理对象

   项目未来计划支持多人联机，因此设计时需要考虑：
   - 前后端职责分离。
   - 游戏逻辑与表现层适当解耦。
   - 对象池等资源管理机制。
   - 玩家、场景和世界状态未来的扩展与同步。

   当前不要求一次性实现完整联机功能，但需要避免采用明显妨碍后续扩展的设计。

4. **场景制作范围**

   当前暂时不需要制作玩家醒来之后的正式游戏场景，也不需要提前完成后续探索区域。

   但这不意味着可以省略底层框架：场景管理、场景切换、玩家对象、游戏状态等必要结构仍然需要搭建，并保证后续能够接入新场景。

5. **开始界面 UI**

   本轮需要制作游戏开始界面。

   UI 整体要求现代化，与游戏的视觉风格保持统一。当前尚未开始正式游戏场景的制作，因此不要求提前完成所有游戏内 UI，后续将随着场景和玩法开发逐步完善。
